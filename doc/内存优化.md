我查完这套库后，当前设备被 AIOS 识别和鉴权，实际走的是一条“`register/auth -> websocket -> sync`”链路，但仓库里同时存在两套实现，真正起作用的是旧链路里的 [main/aios_auth.cc](/home/wzq/project-haro/main/aios_auth.cc:432) 配合 [main/ota.cc](/home/wzq/project-haro/main/ota.cc:100)。新的 [main/aios/aios_http_client.cc](/home/wzq/project-haro/main/aios/aios_http_client.cc:21) 目前更像占位，初始化了 header，但还没有真正发 `/device/register` 或 `/device/auth`。

**设备怎么被 AIOS 识别**
设备在 HTTP 注册/认证阶段，主要靠 `sn` 和注册后的 `access_key/access_secret` 被识别。
在 [main/aios_auth.cc](/home/wzq/project-haro/main/aios_auth.cc:450) 里，`sn` 的来源顺序是：
1. NVS 里的 `aios/sn`
2. `CONFIG_AIOS_DEVICE_SN`
3. 都没有就回退到 `SystemInfo::GetMacAddress()`，也就是 Wi‑Fi STA MAC，[main/system_info.cc](/home/wzq/project-haro/main/system_info.cc:36)

首次注册时，请求 `/device/register` 带的是 `device_product_id`、`tenant_user_id`、`sn`，[main/aios_auth.cc](/home/wzq/project-haro/main/aios_auth.cc:512)。注册成功后，返回的 `access_key/access_secret` 会写进 NVS 的 `aios` 命名空间，[main/aios_auth.cc](/home/wzq/project-haro/main/aios_auth.cc:547)；对应的持久化字段定义在 [main/settings.cc](/home/wzq/project-haro/main/settings.cc:91)。

**鉴权怎么做**
HTTP 鉴权时，设备调用 `/device/auth`，请求体里放 `access_key/access_secret/sn/region/language`，[main/aios_auth.cc](/home/wzq/project-haro/main/aios_auth.cc:466)。这一层不是明文直发，而是按文档里的 RSA + AES 方案加密：随机生成 AES key，用公钥加密 AES key，请求体再用 AES 加密，并带上 `Authorization` 和 `X-Encryption-Data`，[main/aios_auth.cc](/home/wzq/project-haro/main/aios_auth.cc:328)；协议说明在 [docs/AIOS服务通讯加密流程.md](/home/wzq/project-haro/docs/AIOS服务通讯加密流程.md:28)。

`/device/auth` 成功后，服务端返回：
- `user.token`
- `user.id`
- `ws.url`
- `profile_device.config_agentic_id`

代码把它们写入 `websocket` 配置：[main/ota.cc](/home/wzq/project-haro/main/ota.cc:110)。其中最关键的是：
- `token` -> WebSocket `Authorization: Bearer ...`
- `user.id` -> WebSocket `X-Device-Id`
- `config_agentic_id` -> WebSocket `X-Bot-ID`

WebSocket 建连时，这几个 header 在 [main/protocols/websocket_protocol.cc](/home/wzq/project-haro/main/protocols/websocket_protocol.cc:195) 设置。也就是说，**AIOS 在 WebSocket 阶段真正识别设备，靠的是 `X-Device-Id`，而这个值不是本地 UUID，也不是 MAC，而是 `/device/auth` 返回的 `user.id`**。这点和文档一致：[docs/AIOS设备注册认证流程.md](/home/wzq/project-haro/docs/AIOS设备注册认证流程.md:149) 明确写了 `user.id` 也是 ws 里的 `X-Device-Id`，[docs/AIOS-websocket协议.md](/home/wzq/project-haro/docs/AIOS-websocket协议.md:161) 也说明服务器靠 `X-Device-Id` 识别设备。

WebSocket 连上后，还会再调用一次 `/device/sync`，这里用的是 Bearer token，[main/protocols/websocket_protocol.cc](/home/wzq/project-haro/main/protocols/websocket_protocol.cc:332) 和 [main/aios_auth.cc](/home/wzq/project-haro/main/aios_auth.cc:600)。

**几个容易混淆的点**
- 本地 `Board::GetUuid()` 是设备本地生成并持久化的 UUID，[main/boards/common/board.cc](/home/wzq/project-haro/main/boards/common/board.cc:15)，更多像本地 `Client-Id`，不是当前 AIOS 主识别 ID。
- MAC 地址主要是 `sn` 的兜底来源，或者旧兼容 header 的 `Device-Id`，不是最终 AIOS ws 主身份。
- 仓库里现在有“两套 AIOS 接入代码”并存：旧的 `aios_auth.cc` 是真的在做鉴权；新的 `aios_http_client.cc` 目前还没把 register/auth 实现完整。

会，但要分三层看。

第一层，**是否都被编进固件镜像**：会。  
`main/CMakeLists.txt` 同时把 [aios_auth.cc](/home/wzq/project-haro/main/CMakeLists.txt:34) 和 [aios/aios_http_client.cc](/home/wzq/project-haro/main/CMakeLists.txt:33) 加进了 `SOURCES`，所以两套代码都会进最终 firmware。

第二层，**是否都会在运行时被执行到**：当前 AIOS 配置下，大概率也会。  
启动激活流程里先 `CheckNewVersion()`，[main/application.cc](/home/wzq/project-haro/main/application.cc:375)；而它会进 [Ota::CheckVersion()](/home/wzq/project-haro/main/ota.cc:92)，这里明确创建了临时的 `AiosAuthClient` 并调用旧链路鉴权，[main/ota.cc](/home/wzq/project-haro/main/ota.cc:102)。  
紧接着 `ActivationTask()` 又会走新的 `aios_http_client_` 路径，[main/application.cc](/home/wzq/project-haro/main/application.cc:378)。所以现在不是“二选一”，而是**先跑旧套，再碰到新套**。

第三层，**是否都会长期占用 RAM**：不是。  
- 旧套 `AiosAuthClient` 主要是临时对象，像 [main/ota.cc](/home/wzq/project-haro/main/ota.cc:102) 和 [main/protocols/websocket_protocol.cc](/home/wzq/project-haro/main/protocols/websocket_protocol.cc:339) 里都是栈上现建现用，用完就释放。  
- 新套 `AiosHttpClient` 是 `Application` 的成员指针 [main/application.h](/home/wzq/project-haro/main/application.h:142)，创建后会保留在堆上，至少会比旧套更“常驻”。它本身持有 `credentials_`、`crypto_` 等成员，[main/aios/aios_http_client.h](/home/wzq/project-haro/main/aios/aios_http_client.h:27)。

所以结论是：

- **两套都会被编进固件**
- **当前启动流程里两套都会碰到**
- **但长期占 RAM 的主要是新套 `aios_http_client_`**
- **旧套 `aios_auth` 更多是按需临时上栈，不是常驻对象**

更准确地说，当前系统是“**旧套在真正做鉴权，新套也被创建了，但还是半成品/占位**”。如果你要，我可以继续把“启动时两套各自执行到哪一步”按时序列出来。
