# TM-05 错误监控与用户反馈闭环

优先级: P2

## 目标

在“对话 + 舵机执行”全过程建立可感知错误闭环：发生错误时，系统不仅记录，还要能对用户反馈。

## 范围

- 错误分类体系
- 统一错误事件模型
- 用户可感知反馈（屏幕/语音）
- 自动恢复与降级策略

## 错误分类（建议）

1. 协议错误
- JSON 结构不合法
- 字段缺失/类型错误

2. 业务错误
- 动作参数越界
- 不支持的动作目标

3. 执行错误
- 舵机驱动调用失败
- 动作执行超时

4. 系统错误
- 内存不足
- 任务阻塞
- 连接异常

## 用户反馈策略

- 屏幕: 简短错误码 + 人类可读说明
- 语音: 失败时直接反馈“我尝试了，但执行失败”
- 日志: 记录 `error_code/cause/turn_id/action_id`

## 关于“舵机坏了但设备不自知”

- 无位置回读舵机无法100%确认“物理是否真的动了”。
- 现阶段先做“软失败检测”（超时/驱动失败）。
- 若要硬确认，需要加反馈硬件（回读舵机/电流检测/IMU/编码器）。

## 建议修改文件

- `main/application.cc`
- 舵机执行模块（TM-02 产物）
- 新增 `main/telemetry/error_reporter.*`（建议）

## 验收标准

- 所有失败路径都有统一错误码。
- 用户在失败时能得到可理解反馈。
- 错误日志可关联到具体会话和动作。

## 交付物

- 错误码表
- 用户反馈文案表
- 自动恢复策略说明
