# TM-01 会话失忆与莫名重启修复

优先级: P0（最高）

## 目标

一次开机周期内保持稳定会话身份，减少“每轮都像新用户”的体验问题；同时定位并修复“聊几轮后自动重启”的根因。

## 背景问题

- 现象 A: 设备对话上下文无法持续，表现为“失忆”。
- 现象 B: 对话进行一段时间后设备自动重启。

## 范围

- 会话标识体系（boot_session_id / dialog_turn_id）。
- websocket 生命周期策略（开机会话内连接保持）。
- 重启原因采集（reset reason / panic / wdt / brownout / oom）。
- 运行时资源打点（heap/psram/栈水位/关键队列）。

## 非目标

- 舵机语义控制（由 TM-02 负责）。
- 完整日志平台接入（由 TM-03 负责）。

## 关键实现要求

1. 会话机制
- 启动生成 `boot_session_id`，直到下次重启前不变。
- 每轮问答生成 `dialog_turn_id`。
- websocket 不再在每次回 idle 时立即关闭，改为“空闲超时关闭”（例如 60-180s，可配置）。

2. 上下文机制
- 本地缓存最近 N 轮对话摘要（建议 N=10）。
- 重连后先上报摘要（或附带在首轮请求 metadata 中）。

3. 重启诊断
- 启动即打印并上报 `esp_reset_reason()`。
- 崩溃前后关键指标落盘到循环缓冲（NVS 或 RAM ring buffer）。

4. 资源监控（最小集）
- 每 1s: `free heap/min heap/free psram/min psram`
- 每 5s: 关键 task 高水位
- 每轮结束: 峰值队列深度和总耗时

## 建议修改文件

- `main/application.cc`
- `main/application.h`
- `main/protocols/websocket_protocol.cc`
- `main/system_info.cc`
- `main/settings.cc`（如需新增配置）

## 验收标准

- 连续 20 轮对话内不出现“每轮都失忆”的主观体验。
- 至少 60 分钟压力对话运行无自动重启。
- 若重启发生，日志能明确分类原因（wdt/panic/brownout/oom/手动重启）。

## 交付物

- 代码修改
- 关键日志样例（会话 ID 连续、重启原因日志）
- 一页复盘: 根因、修复点、剩余风险
